# Приёмник лазерного канала (Hamming(7,4))

Декодирование цифры 0–15, переданной лазером дрона, по видео с камеры.
Приёмная часть к передатчику [`laser_tx.py`](https://github.com/ghamlet/Arhipelag_2026/tree/main/Integration_of_laser_sensor_and_signal_reception_system_into_AUV_%26_UAV_system/Final_stage/laser).

| Файл | Назначение |
|---|---|
| `rx.py` | приёмник: детектор пятна + декодер |
| `test_rx.py` | синтетический тест всех 16 цифр |
| `video2.mp4` | пример записи (64 с, 1080×720, 30 fps) |
| `rx_original_backup.py` | исходная версия до переработки |

## Быстрый старт

```bash
python rx.py video2.mp4            # разбор файла с окнами и осциллограммой
python rx.py video2.mp4 --report   # быстрый прогон, только итоговый отчёт
python rx.py 0                     # живая камера (индекс устройства)
python rx.py 0 --no-display        # headless на дроне
python test_rx.py                  # проверка декодера на всех 16 цифрах
```

Нужны `opencv-python` и `numpy`. В окне: `q` — выход, `r` — сброс декодера.

### Ключи

| Ключ | Смысл |
|---|---|
| `--roi auto` | по умолчанию: ищем пятно внутри зелёной мишени, если мишени в кадре не бывает вовсе — по всему кадру |
| `--roi board` | только внутри мишени; нет мишени — нет приёма |
| `--roi full` | всегда по всему кадру (**менее надёжно**, см. «Ограничения») |
| `--report` | без окон, только отчёт |
| `--no-display` | без окон, но с подробным логом |
| `--realtime` | проигрывать файл со скоростью съёмки, а не максимально быстро |
| `--loop` | повторять файл по кругу |
| `--red-threshold N` | фиксированный порог «красноты» вместо адаптивного |
| `--min-score`, `--min-margin` | пороги приёма пакета |

## Протокол

Так его формирует передатчик:

```
set_laser(0), пауза 100 мс
СТАРТ:   ON 600 мс, затем OFF 100 мс
7 бит, каждый занимает слот 250 мс:
    бит = 1  ->  ON 200 мс + OFF 50 мс
    бит = 0  ->  OFF 250 мс
конец:   лазер выключен
```

Данные — Hamming(7,4) в раскладке `[p1, p2, d1, p3, d2, d3, d4]`,
`p1 = d1^d2^d4`, `p2 = d1^d3^d4`, `p3 = d2^d3^d4`. Код исправляет одну ошибку.
Полный пакет — 2.4 с, минимальное расстояние между кодовыми словами — 3 бита.

Кодовые слова (их печатает `test_rx.py`):

```
0=0000000  1=1101001  2=0101010  3=1000011  4=1001100  5=0100101  6=1100110  7=0001111
8=1110000  9=0011001 10=1011010 11=0110011 12=0111100 13=1010101 14=0010110 15=1111111
```

## Почему предыдущая версия не работала

Четыре независимые причины, каждая фатальная сама по себе.

**1. HSV-фильтр не мог сработать никогда.** Было
`LOWER=(255,51,80)`, `UPPER=(60,255,255)`: нижняя граница Hue *выше* верхней,
поэтому `cv2.inRange` всегда возвращал пустую маску. Лазер не находился ни в
одном кадре ни при каких условиях.

**2. Модель протокола неверна в принципе.** Код мерил длительность между
фронтами и считал её одним битом. Но у нуля нет своего фронта:

* два нуля подряд сливаются в одну паузу 500 мс;
* несколько единиц подряд сливаются в один длинный импульс — пауза 50 мс между
  ними на 30 fps (кадр 33 мс) видна лишь примерно в половине случаев.

Декодирование «фронт = бит» на таком сигнале невозможно, а не просто неточно.

**3. `time.time()` при разборе файла.** Обработка идёт не в реальном времени,
поэтому все измеренные длительности были случайными. Для файла нужен таймкод
видео (`CAP_PROP_POS_MSEC`), для камеры — системное время.

**4. Падение при отрисовке.** `(center-30, center-radius-10)` — вычитание `int`
из кортежа, `TypeError`. Не проявлялось только потому, что из-за п.1 пятно
никогда не находилось.

## Как работает сейчас

### Детектор пятна

Лазерная точка на мишени — это **белое пересвеченное ядро с красным гало**.
Признак: «краснота» `R − max(G, B)` с порогом, адаптирующимся к фону
(обновляется только пока лазер считается погашенным, иначе само пятно поднимет
порог и детектор ослепнет).

Поиск идёт **только внутри зелёной мишени**: без этого красный корпус робота
читается как постоянно горящий лазер и фронтов не возникает вообще. Мишень
находится по зелёной рамке, ROI расширяется на 8 %.

Дополнительно: ограничения на размер/компактность/вытянутость пятна, требование
пересвеченного ядра (проверяется по габаритному прямоугольнику блоба, а не по
маске — центр пятна белый, его «краснота» ≈ 0, в маску попадает только гало),
и триггер Шмитта по площади против дребезга на фронтах.

### «Не знаю» вместо «не горит»

Самое важное для надёжности. Если мишени в кадре нет, кадр помечается
**невалидным**, а не «лазер погашен». Иначе пропавшая мишень читается как
длинная пауза и складывается в убедительный, но выдуманный пакет — особенно в
цифру 0, у которой все биты нулевые, то есть «старт-импульс и дальше тишина».
На этом ловились ложные цифры 0 и 7 со score 0.93–0.97.

Невалидные кадры получают нулевой вес, и пакет принимается только если
`coverage` — доля реально увиденного пакета — не ниже `MIN_COVERAGE`.
Сравнение идёт с ожидаемой длительностью, а не с тем, что оказалось в буфере,
иначе обрезанный на конце записи пакет выглядел бы «полным».

### Декодер: согласованная фильтрация

Вместо измерения фронтов:

1. Ловим кандидата на начало пакета: фронт после паузы, дальше засвеченное окно
   600 мс. Проверяется **долей** засветки, а не непрерывной длиной, — иначе один
   битый кадр внутри старт-импульса убивает весь пакет.
2. Все 16 корректных кодовых слов строятся как эталонные осциллограммы вместе
   со старт-битом.
3. Перебор сдвига ±120 мс и длины слота 240–260 мс; совпадение считается **по
   времени**, вес отсчёта = длительность кадра. Отсюда независимость от fps и
   устойчивость к выпавшим кадрам.
4. Выравнивание выбирается по всей осциллограмме (старт-бит — надёжный якорь),
   а сама цифра — только по битовой части: старт-бит одинаков у всех 16 гипотез
   и лишь размывает отрыв.
5. Пороги: `score`, отрыв от второго места (`margin`) и `coverage`. Не прошло —
   честный отказ вместо случайной цифры.

Ошибки исправляются автоматически: сравнение идёт только с корректными
кодовыми словами, то есть Hamming работает как часть фильтра, а не отдельным
шагом. Медиана по 3 кадрам убирает одиночные сбои детектора, а арбитраж между
близкими кандидатами не даёт мусорному блику «съесть» реальный пакет.

**Паузы 50 и 100 мс из подсчёта исключены.** Информации они не несут
(в передатчике всегда OFF), зато камера их регулярно замазывает. Их исключение
и убирает системную ошибку от слипающихся единиц.

## Результаты

### На `video2.mp4`

**13 из 13 реальных посылок, все `5`** (это дефолтная цифра в `laser_tx.py`),
ни одной неверной. `score` 0.914–1.000, `margin` 0.140–0.429.

Отклонён 1 кандидат — ложный старт от слипшегося импульса. Ещё одна посылка на
42.5 с физически не декодируема: мишень ушла из кадра, из трёх импульсов виден
один. Раньше на этом месте выдавалась случайная цифра, теперь — отказ.

### `test_rx.py`

В записи есть только цифра 5, поэтому остальные 15 проверяются на
смоделированном сигнале. Модель камеры честная: кадр считается «лазер горит»,
если импульс попал в окно экспозиции, — отсюда сами собой получаются реальные
эффекты (импульс 200 мс выглядит как 233 мс, единицы подряд слипаются).

| Сценарий | Результат |
|---|---|
| 30 fps, идеально | 128/128 |
| 30 fps, дрожание кадров 8 мс | 128/128 |
| 30 fps, 10 % кадров потеряно | 128/128 |
| 30 fps, 3 % сбоев детектора | 128/128 |
| 15 fps (слабая камера) | 128/128 |
| 60 fps | 128/128 |

Итого **768/768 без ошибок** в расчётных условиях.

## Ограничения

* **`--roi full` заметно менее надёжен**: на `video2.mp4` 8 верных из 11 и три
  ложных нуля. Поиск по всему кадру без опоры на мишень — принципиально более
  сложная задача. Для штатной постановки он не нужен: `--roi auto` находит
  мишень сам. На этот режим выводится предупреждение.
* **Вне расчётных условий** (15 fps + 10 % потерь + 3 % шума одновременно)
  остаётся ~1 % неверных декодирований. `test_rx.py` печатает этот сценарий
  отдельным справочным блоком. Передатчик повторяет посылку, поэтому счётчик
  `подряд×N` в логе снимает и это.
* **Цифра 0 — слабое кодовое слово протокола**: её осциллограмма это
  «старт-импульс и дальше тишина», поэтому любой одиночный импульс ~600 мс
  похож на неё. Защита — проверка качества старт-импульса и `coverage`.
* Латентность ответа — около 3.9 с от начала посылки: 2.4 с сам пакет плюс
  окно арбитража между кандидатами.

## Настройка под свои условия

Все параметры — константы в начале `rx.py`.

Протокол (`START_ON`, `BIT_PULSE`, `BIT_GAP`, `NBITS`) менять только вместе с
передатчиком. Остальное — под свою съёмку:

| Константа | Когда трогать |
|---|---|
| `BOARD_HSV_LO/HI`, `BOARD_MIN_AREA` | другой цвет или размер мишени |
| `RED_TH_MIN/MAX`, `RED_TH_MARGIN` | другой лазер или освещение; либо `--red-threshold` |
| `AREA_LO/HI`, `ON_ENTER/ON_EXIT` | пятно сильно мельче (большая дистанция) |
| `MAX_SPOT_FRAC`, `CORE_MIN_V` | другая поверхность мишени |
| `MIN_SCORE`, `MIN_MARGIN`, `MIN_COVERAGE` | баланс «отказы против ошибок» |
| `SLOT_GRID`, `OFFSET_GRID` | уход тайминга передатчика |

Диагностика: `--no-display` печатает причину каждого отказа со значениями
`score` и `margin`; в окне снизу рисуется осциллограмма детектора (зелёное —
лазер горит, серые полосы — мишени не видно, кадр невалиден).
